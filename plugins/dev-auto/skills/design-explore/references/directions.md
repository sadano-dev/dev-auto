# 方向性の候補とサブエージェントへの依頼文

## 方向性の候補集

題材に合わせて 10 個を選び、名前と狙いは題材の言葉で書き直す。候補が題材に合わなければ差し替える。1 案につき「変える軸」は 2〜3 個に絞り、案どうしで軸がなるべく重ならないようにする（比べたときに違いが分かるように）。

| 候補 | 変える軸 | 向いている題材・利用者 |
|---|---|---|
| シアター（ダーク） | 暗い地、主役（映像・画像）だけを明るく、主役の面積を拡大 | 動画・写真・音楽など「見る・聴く」が中心 |
| エンティティ単位の色 | サイトの地は中立、リスト・プロジェクト・チームなど単位ごとに色を持たせる | ユーザーが作ったものに愛着を持つサービス |
| 高密度インデックス | 行レイアウト・表組み・読みやすい UD 書体で一覧性を優先 | 常連・作り手・管理用途 |
| 画像主導ギャラリー | 枠や罫線を消して画像の面積を最大化、一覧にもサムネ | 中身が絵になるサービス、初見の人を惹きつけたい |
| エディトリアル | 明朝などの見出し書体と余白で「編集された特集」に見せる | キュレーション・読み物 |
| ポップ・ステッカー | 太線・硬い影・丸み・ビビッドな色 | ファン活動・若い利用者・遊び |
| モノクロ＋ 1 色アクセント | 無彩色に、サービスの行為を表す 1 色だけ | 行為そのものが特徴のサービス（「線を引く」「切り取る」など） |
| ブランド強化 | ロゴとモチーフを作り、トップで機能を図解する | 初見の人に何のサービスか伝わりにくい |
| 中心概念の可視化 | 時間・量・進捗など、文字で書いている値を図（バー・グラフ）で見せる | 数値や範囲がサービスの中心 |
| モバイルファースト・アプリ風 | ボトムナビ、大きな操作バー、シート | SNS などからスマホで来る利用者が多い |

選んだ 10 案の組み合わせを見直し、次のどれかに当てはまったら入れ替える:

- 同じ軸（例: 色だけ）を変えている案が 3 つ以上ある
- 題材と関係なく、どのサービスにも同じ案が出てくる（その題材ならではの理由を書けない）
- 現行と見分けがつかない

## サブエージェントへの依頼文

以下をそのまま渡し、`<...>` を埋める。

```
デザイン検討用のモックアップを 1 案作ってください。

- コピー元: <出力先>/00-current.html（現行デザインの再現。ボード外枠・フィクスチャ・スマホ枠を複製するスクリプトを含む）
- 作るファイル: <出力先>/<NN>-<slug>.html（このファイル以外は編集しない。git stash は使わない）
- 案の名前: <名前>
- 狙い: <誰に何を感じてほしいか、何を優先し何を犠牲にするか>
- 変える軸: <2〜3 個>
- 題材: <サービスの 1 行説明と主な利用者>

守ること:
1. BOARD（外枠）部分の CSS とスクリプトは変えない。.app 以下のトークンと CSS を書き換えるのが基本。マークアップの変更は狙いに必要な最小限にし、変えたらメモの「レイアウト」に書く
2. 内容（文言・件数・フィクスチャ）は 00 と同じにする。フィクスチャの難しい場合（<複数のまとまり・エラー・空・未設定など>）をこの案でどう見せるかを考え、メモの「難しい場合の見せ方」に書く
3. PC 1280px とスマホ 375px の両方で横はみ出しを出さない。レイアウト切り替えは @media ではなく @container app を使う。grid の列は 1fr ではなく minmax(0, 1fr) にする
4. 文字色と背景のコントラストは WCAG AA（本文 4.5:1、大きな文字 3:1）を満たし、実測値をメモに書く。タップ領域 44px を保つ。状態を色だけで示さない
5. 書体を変える場合は Google Fonts の <link> を DIRECTION-FONTS の位置に置き、必ず代替フォントを並べる
6. ボード上部のメモ（board-head）を埋める: 狙い（3〜4 文）、トークンファイルとの差分（--name: 旧 → 新）、書体、形、レイアウト、採用時の影響範囲、アクセシビリティ、難しい場合の見せ方
7. 実在の他社のロゴ・名称・画面をそのまま使わない
8. ありがちな生成デザインを避ける: 全部同じ角丸・同じ薄い影のカード、全見出しの上の英大文字ラベル、意味のない 01/02/03 の番号、装飾だけのグラデーション

終わったら、作ったファイルのパスと、狙い・変えた軸・難しい場合の見せ方を 3 行で返してください。
```

## 組み合わせ案を作るときの注意

- 土台の案をコピーし、ほかの案から持ってくる要素を足す。持ってきた要素どうしが競合する場合（例: サイト全体のアクセント色と、エンティティ単位の色）は、片方を中立（黒・グレー）にして、決めた理由をメモに書く。どちらを中立にするか迷うなら、手順 6 の比較（切り替えボタン）に回す
- 元になった案の番号をメモの先頭に書く（「組み合わせの元: 04 + 02 + 08」）
- 組み合わせで新しく生まれる設定（例: ユーザーが選ぶテーマ色）は、設定画面のモックも同じファイルに足す。選択肢は色名などの文字を併記した radio にし、プリセットはキーで保存する（コントラストを保証できるように）など、実装時の前提もメモに書く

## 作例（OshiClip: YouTube の区間クリップを集めて共有するサービス）

- 画面: トップ（新着の公開リスト）と、リスト詳細（プレイヤー＋クリップ一覧）
- フィクスチャ: 4 本の動画（2 チャンネル、うち 1 本は再生不可）から 8 クリップを集めたリスト。実装どおり動画ごとに見出しを付けてまとめる。DB に動画タイトルが無いので「動画 N」と表示し、チャンネル名はプレイヤーが読み込むまで不明
- 10 案: シアター / 推し色（リストごとの色）/ 高密度インデックス / サムネイル主導ギャラリー / エディトリアル / ポップ・ステッカー / モノクロ＋蛍光マーカー / ブランド強化（区間ブラケット [ ] のロゴ）/ タイムライン主導（区間をバーで表示）/ モバイルファースト・アプリ風
- 反応: 「リスト詳細は複数動画のデータで見たい」→ 全案のフィクスチャを変更。「ギャラリーを土台に推し色とロゴを合わせたい」→ 組み合わせ案 11 を追加し、テーマ色を選ぶリスト編集画面も足した。「ロゴは画像生成で作るので仮で」「トップのイラストは不要」。「サービスの色が地味」→ 黒・墨グレー・赤を切り替えで比較（赤は `#ff0033` が白地 3.96:1 のため `#e60023` に調整）→ 推し色が映える黒で決定
